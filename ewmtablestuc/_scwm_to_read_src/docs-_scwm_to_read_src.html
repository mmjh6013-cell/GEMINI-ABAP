Code listing for : Documentation - /SCWM/TO_READ_SRC

Description :

SHORT TEXT
 Read WT for Source Data

FUNCTIONALITY
 You can use this function module to read warehouse tasks (WTs) based on
 source data such as source storage bin or source handling unit (HU). The
 data retrieval is controlled by the input parameters.
 The system validates the passed input parameters before the retrieval.
 The data can be retrieved from the database or from internal memory
 tables.
 The buffered read only works if the same function module is called again
 with the same combination of input parameters. The input parameter
 combination is stored in an internal index table which is validated at
 the beginning of the data retrieval. For example, if you call the
 function module the first time with several storage bins in the input
 parameter <NP>IT_LGPLA</> and the second time with a single storage bin
 in <NP>IV_LGPLA</>, the buffer is not used even if the storage bin was
 part of the first call.
 The internal memory tables are cleared after the central EWM cleanup
 (method <NP>/SCWM/CL_TM=>CLEANUP</>) is called.
 Parameters
 This function module has the following parameters:
 <NP>IV_LGNUM</>
 See <DS:DE./SCWM/LGNUM>Warehouse Number</>
 <NP>IV_LGTYP</>
 See <DS:DE./SCWM/LGTYP>Storage Type</>
 <NP>IT_LGTYP</>
 Table of single storage type values
 <NP>IV_LGPLA</>
 See <DS:DE./SCWM/LGPLA>Storage Bin</>
 <NP>IT_LGPLA</>
 Table of single storage bin values
 <NP>IV_RSRC</>
 Resource
 <NP>IT_RSRC</>
 Table of single resource values
 <NP>IV_TU_NUM</>
 Internal transportation unit (TU) number
 <NP>IT_TU_NUM</>
 Table of single TU values
 <NP>IV_HUIDENT</>
 Handling unit
 <NP>IT_HUIDENT</>
 Table of single handling unit values. The structure which is basis of
 this table contains other fields such as <NP>LGNUM</> (<ZK>Warehouse
 Number</>) and <NP>VHI</> (<ZK>Virtual Handling Unit Indicator</>).
 These fields are not taken into account for the retrieval. Therefore
 setting the field <NP>HUIDENT</> is sufficient.
 <NP>IV_NOBUF</>
 Controls whether the function module reads data from internal memory
 tables or from the database. The following values are possible:
 Space: Reads data from memory
 X: Reads data from database
 <NP>IV_ADD_TO_MEMORY</>
 Adds the retrieved WTs to internal memory tables. If you call the
 function module with the same values in the input parameter again, the
 data is retrieved from the internal memory table instead of the
 database. Reading from the internal memory tables is faster than reading
 from the database. The system does not read from internal memory tables
 if you set the parameter <NP>IV_NOBUF</> to 'X' or if you call the
 function module with a combination of input parameters the first time.
 The following values are possible:
 Space: Does not add retrieved warehouse tasks to internal memory tables
 X: Default value. Adds retrieved warehouse tasks to internal memory
 tables.
 <NP>IV_NO_WAITING</>
 Does not read open WTs and WT log entries with the status <ZK>Waiting</>
 from internal memory tables or from the database. The following values
 are possible:
 Space: Default value. Returns warehouse tasks with the status
 <ZK>Waiting</>.
 X: Does not return warehouse tasks with the status <ZK>Waiting</>
 <NP>IV_LOCK</>
 Not used in this function module
 <NP>ET_ORDIM_O</>
 Result table with open WTs
 <NP>ET_ORDIM_C</>
 Result table with confirmed and canceled WTs
 <NP>ET_ORDIM_L</>
 Result table with WT logs. WT log entries are not related to the
 existing application log entries which are written, for example, during
 WT creation.
 <NP>ET_ORDIM_E</>
 Result table with exception codes for WTs
 <NP>ET_ORDIM_H</>
 Result table with implicit product movements for HU WTs. The basis for
 this exporting parameter is the database table <NP>/SCWM/ORDIM_H</>.
 Entries to this database table are written based on the setting
  <DS:DE./SCWM/DE_HUMOVE_PROD>Do Not Explode Products</> (field
 <NP>HUMOVE_PROD</>) in the Customizing for storage types. Accordingly,
 the system cannot read any entries if the storage types are customized
 not to write product movement data.
 <NP>ET_ORDIM_LS</>
 Result table with serial numbers for WT logs. Entries in this table are
 only written for products with a serial number profile with the serial
 number requirement <ZK>C</>. WT log entries are not related to the
 existing application log entries which are written, for example, during
 WT creation.
 <NP>ET_ORDIM_OS</>
 Result table with serial numbers for open WTs. Entries in this table are
 only written for products with a serial number profile with the serial
 number requirement <ZK>C</>.
 <NP>ET_ORDIM_CS</>
 Result table with serial numbers for confirmed WTs. Entries in this
 table are only written for products with a serial number profile with
 the serial number requirement <ZK>C</>.
 <NP>ET_ORDIM_HS</>
 Result table with serial numbers for HU movements for WTs. Entries in
 this table are only written for products with a serial number profile
 with the serial number requirement <ZK>C</>.
 Exceptions
 <NP>WRONG_INPUT</>
 <NP>NOT_FOUND</>
 <NP>FOREIGN_LOCK</>
 Function group
 <NP>/SCWM/TO_SEL</>
EXAMPLE
 
HINTS
 If the storage bin parameter is filled, the storage type parameter must
 also be filled.
 The exception <NP>WRONG_INPUT</> is raised if the input parameters
 contain an incorrect combination of the following list:
 All the import parameters are blank except warehouse number
 A blank warehouse number parameter is only allowed with TU selection
 At least one of the storage bin, HU, TU, and resource parameters must be
 filled
 Either the single value or the table of an input parameter must be
 filled
 The exception <NP>NOT_FOUND</> is raised if the system does not find an
 open WT, a confirmed WT, and WT logs.
 The exception <NP>FOREIGN_LOCK</> is never raised because the import
 parameter <NP>IV_LOCK</> has no implementation.
